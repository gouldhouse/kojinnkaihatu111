# 要件定義書:成長ライブラリ(仮称)

## 1. 目的
成長を「なんとなく」で終わらせず、次も再現できるものにする。
1つの成長体験を4つの問いで言語化し、自分だけのライブラリとしてアーカイブする。

## 2. 課題
- うまくいった・成長したと感じても、なぜそうなったか・何が変わったかを言葉にしないまま流れてしまう
- 振り返ろうと思っても後回しになり、忘れてしまう

## 3. ターゲット
自分(成長したい大学生)。自分だけが使う個人の記録帳。他人とは共有しない。

## 4. コア体験
- 課題にぶつかったその場で「課題」だけ書いて一時保存できる
- アクションをとり、結果が出て、考え方が変わったら、あとから追記して記録を完成させる
- 1つの記録が成長と一緒に育っていく

## 5. 4つの問い(記録の中身)
| # | 問い | 書く内容 |
|---|---|---|
| 1 | 課題 | 何に直面していたか、何がうまくいっていなかったか |
| 2 | とったアクション | それに対して実際に何をしたか |
| 3 | アクションの結果 | どうなったか |
| 4 | パラダイムシフト | 自分の中で考え方が変わったこと |

パラダイムシフト欄には、書き方のヒントを placeholder で表示する:
「例:以前は『〜』と思っていたが、『〜』と考えるようになった」

## 6. 機能

### MVP(必ず作る)
**F1. 記録を始める**
- タイトルと課題だけ入力して保存できる
- 保存した記録の状態は「進行中」になる

**F2. 続きを書く**
- 保存済みの記録に、アクション・結果・パラダイムシフトをあとから追記できる
- 4項目(課題・アクション・結果・パラダイムシフト)がすべて埋まったら、状態を自動で「完了」にする
- 1つでも空になったら「進行中」に戻す

**F3. ライブラリ(一覧)**
- 記録をカードで一覧表示する(タイトル・状態・更新日・課題の冒頭)
- 「すべて/進行中/完了」で絞り込みできる
- 並び順:進行中を上、その中で更新日が新しい順
- 進行中のカードには「続きを書く」ボタンを付ける

**F4. 詳細**
- 1件の4項目を上から通して読める
- まだ書いていない項目は「まだ書いていません」と表示し、「続きを書く」へのリンクを出す

**F5. 編集・削除**
- 全項目を編集できる(F2と同じ画面)
- 削除できる(確認あり)

### 余裕があれば(MVPの後)
- F6. パラダイムシフト集:完了した記録のパラダイムシフトだけを一覧表示し、元の記録へ移動できる
- F7. キーワード検索(タイトル・4項目を対象)
- F8. ログイン(公開して使うときに自分の記録を守るため)

## 7. 画面一覧
| 画面 | URL | 機能 |
|---|---|---|
| ライブラリ(一覧) | /records | F3 |
| 記録を始める | /records/create | F1 |
| 詳細 | /records/{id} | F4・F5(削除) |
| 続きを書く/編集 | /records/{id}/edit | F2・F5 |

トップ(/)は /records へリダイレクトする。

## 8. DB設計
### records
| カラム | 型 | 必須 | 備考 |
|---|---|---|---|
| id | bigint | ○ | 主キー |
| title | string | ○ | |
| problem | text | ○ | 課題 |
| action | text | | とったアクション |
| result | text | | アクションの結果 |
| paradigm_shift | text | | パラダイムシフト |
| status | string | ○ | `in_progress` / `completed`。保存時に自動で決める |
| created_at / updated_at | timestamp | ○ | |

## 9. やらないこと
- 他人との共有・閲覧・いいね
- AIによる自動要約や提案
- デプロイ(ローカルで動けばOK)
